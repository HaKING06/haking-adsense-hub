Toplam süre ile İlk Token Süresi (TTFT) neden ayrı ölçülmelidir?

Bir yapay zekâ sohbet uygulamasında kullanıcı “sistem yavaş” dediğinde sorun her zaman modelin saniyede ürettiği kelime sayısı (throughput) değildir. Çoğu vakada kullanıcıyı yoran şey, Gönder tuşuna bastıktan sonra ekranda ilk anlamlı kelimenin belirmesine kadar geçen Time To First Token (TTFT) süresidir. Toplam 14 saniye süren bir yanıt ilk 0,9 saniyede akmaya başlarsa akıcı hissedilir; oysa toplam 8 saniye sürüp ilk 7 saniye boş ekran gösteren bir sistem bozuk algısı yaratır.

HaKING AI üzerinde Prompt Modu geliştirilirken yaşanan en büyük kazanımlardan biri, tüm eski sohbet metnini tekrar tekrar modele göndermek yerine yalnızca güncel görev kartını taşımak oldu. Bu hem girdi token yükünü hem de prefill bekleme süresini kontrol altında tutar.

Kendi uygulamanızda gecikmeyi nasıl ölçersiniz?

Tahmine dayalı optimizasyon çoğu zaman yanlış katmana zaman harcatır. İstemci tarafında üç basit zaman damgası kaydetmek darboğazı dakikalar içinde görünür kılar:

İstemci TTFT ve toplam akış ölçümü
const t0 = performance.now();
let tFirstToken = null;
const res = await fetch('/api/chat/stream', { method: 'POST', body });
const tHeaders = performance.now() - t0; // Sunucu uyanma + doğrulama
// İlk token olayında:
if (tFirstToken === null) tFirstToken = performance.now() - t0;

Eğer tHeaders yüksekse odaklanmanız gereken yer soğuk başlangıç, veritabanı bağlantısı veya Turnstile doğrulamasıdır. tHeaders düşük ama tFirstToken yüksekse gecikme model sağlayıcısının prefill veya kuyruk aşamasındadır.

Sıkça Sorulan Sorular

SSE başlıklarında tamponlama nasıl engellenir?

Sunucu yanıtında Content-Type: text/event-stream, Cache-Control: no-cache, no-transform ve ters proxy arkasındaysanız X-Accel-Buffering: no başlıklarını göndermelisiniz.
